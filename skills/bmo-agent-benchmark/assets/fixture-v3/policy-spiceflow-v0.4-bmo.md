# BMO16 v3 policy packet

This benchmark uses a frozen, benchmark-safe projection of the proposed
SpiceFlow 0.4 policy. It is not promotion of the candidate skill.

## Layer order

1. Lock the task, sources, constraints, non-goals and acceptance conditions.
2. Use the Neanderthal-compatible packet contract.
3. Implement or repair the repository.
4. Apply the Clarity Gate to the handoff.
5. Apply the Coverage Gate against the fact ledger.
6. Report evidence with exact proof status.

Divergent Focus is excluded. The common packet also excludes SpiceFlow's
immediate-edit scheduling rule. Only cells assigned `condition-action-first.md`
receive the controlled action-first treatment.

## Packet contract

Interpret every cell through these fields:

- `GOAL`: the concrete artifact outcome.
- `STATE`: initial build or repair of an exact frozen artifact.
- `SOURCE`: the supplied implementation specification and compact source brief.
- `FILES`: the cell's isolated repository root.
- `CONSTRAINTS`: tool, time, turn, egress, safety and fidelity boundaries.
- `NON-GOALS`: authentication, credentials, BMO APIs, tracking, scraping,
  nested agents and unrelated systems.
- `DO`: inspect, edit and leave a coherent root-wired implementation.
- `VERIFY`: perform static self-audit only; deterministic checks belong to the
  outer conductor.
- `STOP`: stop at the hard time/cycle boundary or on an unsafe boundary.
- `RETURN`: changed files, actual work, remaining gaps and proof status.
- `TERMS`: use the stable terms in the local vocabulary below.

## TERMS

- Use `source brief` for `bmo-home-source-brief.json`.
- Use `hero campaign` for one weighted homepage banner item.
- Use `needs navigator` for the six-tab card section.
- Use `reference demo` for the replica artifact.
- Use `deterministic checks` for conductor-owned check, build and artifact
  validation.
- Use `frozen source artifact` for the immutable pre-repair snapshot.
- Use `repair clone` for one isolated copy supplied to a repair cell.

## Clarity Gate

1. Use one term for each concept.
2. Prefer direct action verbs over nominalized phrases.
3. Give each procedural step one action.
4. Put conditions before commands.
5. Use active voice when ownership matters. Passive voice is not forbidden.
6. Remove stacked hedges and empty framing.
7. Preserve exact paths, commands, identifiers, versions, units, errors,
   qualifications and acceptance conditions.
8. Preserve product voice where the page calls for it.

Do not use a controlled-English dictionary, a spelling mandate, blanket bans
on contractions, `-ing`, phrasal verbs or em dashes, or a scalar slop score.

## Coverage Gate

Maintain a fact ledger while working. Before the final handoff, compare the
artifact and response against:

- all required sections and counts in the source brief;
- exact safety labels and non-goals;
- routes, links, identifiers, asset references and interaction conditions;
- responsive and accessibility acceptance conditions;
- detected errors, exceptions, decisions, risks and remaining gaps.

Restore any fact accidentally lost during clarity editing. Do not hide a
missing requirement behind confident prose.

## Evidence Gate

Use only these proof states:

- `verified`: directly observed in files or supplied evidence;
- `unverified`: plausible but not checked;
- `assumed`: necessary assumption stated explicitly;
- `failed`: attempted and did not satisfy its postcondition;
- `deferred`: intentionally left to the conductor or a later pass.

Do not claim a check, build, browser smoke, accessibility pass or responsive
review ran. The outer conductor owns deterministic and browser verification.
Do not request, expose or claim private hidden chain-of-thought.
